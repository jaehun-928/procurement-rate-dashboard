# 조달금리 조회 페이지

## 현재 포함된 내용

- `index.html`: 서버 없이 브라우저에서 여는 조회 화면. 차트, 일별/월별 표, 선택 평균, 기간평균·마감일, 변동폭, CSV, 인쇄, 월간 리뷰, 브라우저 메모와 사용자 이슈 입력을 제공합니다.
- `data.json`: 원천 레코드와 상태 저장 파일. 금리는 0.001%p 단위 정수입니다.
- `조달금리_업데이트.bat`: 사용자가 실행하는 시작 파일. Python 가상환경과 Playwright를 준비하고 수집을 시작한 뒤 보고서 HTML을 엽니다.
- `collector.py`: 네 사이트의 화면 기본 기준일을 직접 확인해 최신 게시 레코드를 가져옵니다. 사이트 날짜를 로컬에서 추정하지 않습니다. 대상 행·만기·금리 형식을 유일하게 식별하지 못하면 성공값을 만들지 않고 실행기록에 `check_required`를 남깁니다.

작업 공간에서 변환한 4개 XLSX의 자료를 `data.json`과 조회 HTML에 반영했습니다. 보유 자료는 2026-01-01부터 2026-11-10까지이며, 2026-11-11 값은 기준 DB에 포함하지 않습니다.

## 조회 화면 사용

`index.html`을 더블클릭해 엽니다. 실행 서버나 추가 앱은 필요하지 않습니다. 브라우저 보안상 `data.json` 직접 fetch가 차단될 수 있으므로 HTML 안에 마지막 수집 데이터도 내장합니다. `collector.py` 실행 후 이미 열린 화면은 새로고침합니다.

이슈와 전망 메모는 해당 브라우저의 로컬 저장소에 들어갑니다. HTML 파일을 다른 PC로 복사해도 이 메모는 이동하지 않습니다. 이슈의 링크와 설명은 사용자 입력이며 미검증으로 취급합니다.

## 실행 방법

1. PC에 Python 3.11 이상과 Google Chrome을 설치합니다.
2. `조달금리_업데이트.bat`을 더블클릭합니다.
3. 첫 실행은 `.venv`와 Playwright를 설치하므로 인터넷 연결이 필요합니다. 설치가 끝나면 4사 페이지를 순차 조회합니다.
4. `data.json`과 HTML에 새 데이터 및 실행 결과가 반영되고, 보고서 페이지가 열립니다.

## 시연 페이지 실행

- `테스트_시연_열기.bat`을 더블클릭하면 시연 서버가 실행되고, 서버 준비 후 `테스트_조달금리_조회.html`이 브라우저에서 열립니다. 최초 실행은 필요한 Python 패키지를 설치하므로 인터넷 연결이 필요합니다.
- 화면의 **11월 11일 금리 수집 시연** 버튼을 누르면 4사 홈페이지에서 표시하는 기준일과 상품별 금리를 실제 브라우저로 조회합니다. 결과는 데모 서버 메모리에만 반영됩니다.
- 페이지를 새로고침하거나 다시 열면 XLS 자료 기준(2026-11-10)으로 초기화됩니다. 운영용 `data.json`, `index.html`, 백업 파일은 시연 중 변경되지 않습니다.
- 시연 서버는 `127.0.0.1:8765`에서 실행됩니다. BAT 창을 열어 둔 채 시연하고, 종료할 때 `Ctrl+C`를 누르거나 창을 닫으세요. 창을 닫으면 버튼 수집도 종료됩니다. 운영 자동 수집은 계속 `조달금리_업데이트.bat`을 사용합니다.
- 실제 페이지가 값을 읽지 못하면 임의 값을 넣지 않고 `확인필요` 상태로 보여줍니다. 사이트 구조나 접근 정책에 따라 수집 결과가 바뀔 수 있습니다.

실행 전 기존 `data.json`과 `index.html`을 `backups` 폴더에 복사합니다. 백업은 30일 뒤 자동 정리됩니다. 갱신 파일은 임시 파일을 완성한 다음 교체합니다. 수집 뒤 HTML을 새로 열어 보고, 이후 자동 예약은 BAT를 Windows 작업 스케줄러에 등록하면 됩니다.

수집기는 사용자 요청대로 별도의 한국 공휴일 달력을 적용하지 않습니다. 각 제공 페이지가 기본값으로 보여주는 기준일을 실제 날짜로 읽습니다. 이 때문에 사이트마다 기준일이 다르면 DB에도 각 사의 확인된 날짜별로 저장되고, 공통 평균은 같은 날짜에 모든 값이 있을 때만 조회 화면에서 계산됩니다.

## 정확도와 현재 제약

- 화면은 둘째 자리로 표시하고 원값 정수로 평균·변동을 계산합니다.
- HTML의 조회 기간 평균은 저장된 관측일 평균입니다. 영업일 달력과 기대 관측일 누락 검사를 연결하기 전까지 완전한 영업일 평균이라고 단정할 수 없습니다.
- 월평균은 실제로 저장된 관측일의 부분 집계입니다.
- 별도 공휴일 달력은 사용하지 않습니다. 제공 사이트의 화면 기준일이 확인되지 않으면 수집 실패로 남깁니다.
- P1 금융 이슈는 사용자가 등록한 데이터만 연결합니다. 자동 뉴스 수집은 없습니다.
- 공개 페이지 UI 변경, 로그인 요구, CAPTCHA, 접근 제한 등은 실행 환경과 시점에 따라 발생할 수 있습니다. 차단 우회나 자동 로그인은 하지 않습니다. 실패 항목은 데이터 상태 보고서와 실행 로그에 남습니다.
- 월간 리뷰는 현재 보유된 관측일에 한정한 부분 리뷰이며 월 마감 검증은 영업일 달력과 과거 XLS 이력을 가져온 뒤 확인해야 합니다.

## 검증한 사항

- JavaScript 문법 검사: `node --check` 통과.
- 기준 XLSX 자료를 내장한 조회 HTML에 대해 JavaScript 구문 검사를 통과했습니다.
- 시연 격리 수집 경로에서 2026-11-11의 4사·2개 상품 총 8개 항목이 모두 정상 식별됐습니다. 조회 당시 값은 NICE 4.422%/3.727%, 한국자산평가 4.448%/3.727%, KIS 4.442%/3.730%, 에프앤 4.454%/3.727%(금융채/국고채 순)였습니다.
- 데모 결과는 `--demo` 표준입출력과 서버 메모리로만 처리합니다. 이 경로는 운영 DB·HTML 파일에 기록하지 않습니다.

## Streamlit 배포

기존 정적 HTML은 유지하고, 배포용 Streamlit 화면을 `streamlit_app.py`로 제공합니다. 이 앱은 기간/상품/평균 방식/평가사 선택, 상단 기간평균·스프레드, 일별 및 월별 Plotly 차트(마우스오버), 일별·월별 표와 CSV 다운로드, 2026년 11월 주요 금융 일정 달력, 전월 금리 리뷰·뉴스와 실시간 수집 버튼을 포함합니다.

### 로컬에서 실행

```powershell
python -m pip install -r requirements.txt
python -m playwright install chromium
streamlit run streamlit_app.py
```

Windows에서 기존 BAT/Collector를 계속 쓸 때는 기본적으로 설치된 Google Chrome 채널을 사용합니다. Streamlit 앱의 수집 버튼은 Playwright 내장 Chromium을 사용합니다.
기존 Windows BAT는 가벼운 `requirements-collector.txt`만 설치하므로 Streamlit 배포 의존성을 추가해도 BAT 실행 과정은 무거워지지 않습니다.

### Streamlit Community Cloud 배포

1. 프로젝트를 GitHub 저장소에 올립니다 (`streamlit_app.py`, `collector.py`, `data.json`, `requirements.txt`, `packages.txt` 포함).
2. Streamlit Community Cloud에서 저장소를 선택하고 앱 진입 파일을 `streamlit_app.py`로 지정합니다.
3. 첫 수집 버튼 클릭 시 브라우저가 설치될 수 있으므로 초기 수집에 시간이 걸릴 수 있습니다.
4. GitHub 저장소의 `data.json`이 최초 기준 데이터입니다. 영구 저장을 원하면 PostgreSQL DB를 준비하고 앱의 Secrets에 아래 값을 넣습니다.

```toml
database_url = "postgresql://USER:PASSWORD@HOST:5432/DATABASE?sslmode=require"
```

PostgreSQL 연결을 처음 사용하면 앱이 상태 테이블을 만들고, 기준 `data.json`을 한 번 적재합니다. 이후 수집 버튼을 누를 때마다 직전 JSON 스냅샷을 `procurement_backups`에 저장하고 최신 자료를 `procurement_state`에 갱신합니다. 복구 시에는 백업 테이블의 원하는 `payload`를 상태 테이블에 다시 넣으면 됩니다. 비밀번호가 포함된 DB URL은 GitHub 파일에 저장하지 말고 Streamlit Secrets에만 입력하세요.

### 배포상 제약

- Community Cloud 파일 시스템은 영구 저장소가 아니므로 PostgreSQL 설정 없이 수집하면 재시작·재배포 후 결과 보존을 보장할 수 없습니다. 앱은 이 상태를 화면에 표시합니다.
- 앱 내 수집 버튼은 서버에서 평가사 사이트에 접속합니다. IP 차단, CAPTCHA, 로그인 요구, 사이트 개편이 있으면 해당 회사는 `확인필요`로 기록될 수 있습니다.
- Community Cloud 앱은 비활성 상태가 길면 절전될 수 있습니다. 이 앱의 버튼은 수동 수집입니다. 매일 자동 수집은 GitHub Actions 등 별도 스케줄러에서 Collector를 실행하도록 추가 설정해야 합니다.
- 일정과 전월 뉴스는 코드에 등록된 2026년 11월 일정 및 2026년 10월 기사 묶음입니다. 매월 자동으로 뉴스·일정을 검색하지 않습니다.
- 커뮤니티 배포 전 저장소 공개 범위, 데이터 접근 권한, 외부 DB 백업 정책을 결정해야 합니다.
